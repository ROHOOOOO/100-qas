# 设计规范

## 设计气质

`Friends Games` 应该像一个轻松、亲密、适合朋友马上开玩的小游戏集合，而不是复杂游戏平台或企业工具。

`100 Q&As` 保持适合朋友慢慢填写的问答体验。`Friends Tycoon` 可以更有游戏感，但仍要清爽、可读、手机端友好。

关键词：

- 温柔
- 清爽
- 私密
- 轻量
- 有陪伴感
- 手机端友好

## 页面布局

- 第一屏直接提供主要操作，不做营销式落地页。
- 首页是“游戏大厅”，直接展示可选游戏。
- 顶部导航要清楚展示 `Friends Games`、`100 Q&As`、`Friends Tycoon`。
- 每个小游戏有独立入口，避免让用户误以为 `Friends Tycoon` 从属于 `100 Q&As`。
- 手机端优先设计。
- 答题页每屏只承载少量信息，避免压迫感。
- 每页固定 5 题，题目和输入框之间要有足够呼吸感。
- 结果页以问题为核心，先看到题目，再看到朋友们的答案。
- Friends Tycoon 桌面端使用左侧环形地图和右侧信息区；移动端地图优先，动态和聊天使用 Tab。
- Friends Tycoon 房间第一屏要优先看到当前回合、可操作按钮、玩家状态和地图。
- Friends Tycoon 桌面宽屏时地图使用横向长方形棋盘，地点卡片要尽量放大，地点名称必须清楚可读。
- Friends Tycoon 移动端保持紧凑地图，避免横向滚动，地点详情通过点击打开。
- Friends Tycoon 地图格子常驻信息保持简洁，只展示编号、地点名、归属或格子类型；买地、升级、过路费等明细按需展示。

## 颜色与视觉

- 避免单一大面积紫色、深蓝、棕橙、米色主题。
- 推荐使用清爽浅底，搭配少量柔和强调色。
- 按钮状态要明确：可点击、不可点击、提交危险确认。
- 不使用复杂装饰，不做过度拟物。
- Friends Tycoon 地图颜色保持克制：无主地产为浅灰色，事件格统一为同一种浅色，玩家地产使用对应玩家的预设代表色。
- Friends Tycoon 玩家颜色限定为 6 个柔和预设色，开局前可选，避免自由取色导致撞色或视觉混乱。

## 交互规范

- 创建房间、复制链接、进入答题、提交答案都要有明确反馈。
- 游戏大厅选择游戏后，应进入对应游戏的独立页面。
- 创建房间页使用清晰的题库来源切换：默认题库 / 自定义题库。
- 自定义题库上传或粘贴后，要立即显示已识别题目数量。
- 自定义题库识别到 1 到 100 题时，生成房间按钮可用，并提示“可以生成房间”。
- 自定义题库为空或超过 100 题时，生成房间按钮仍可点击，并用提示说明问题。
- 草稿保存状态要轻提示，例如“已保存”。
- 提交前必须二次确认。
- 提交后所有输入框不可编辑。
- 未提交进入结果页时，要引导用户先完成答题。
- 本地原型可以展示房间进度和本地玩家切换入口，真实多人版本应收敛为参与者状态展示。
- Friends Tycoon 的聊天区和游戏记录必须分开，避免玩家聊天被系统日志刷掉。
- Friends Tycoon 的房主操作要清楚区分：开始游戏、重开游戏、解散房间、移除玩家。
- Friends Tycoon 的当前回合、当前玩家、可行动按钮要突出，其他玩家的不可用操作应禁用。
- Friends Tycoon 的退出、重开、解散、移除玩家都必须有页面内二次确认。
- Friends Tycoon 破产玩家可继续观看，但不能再行动或发送聊天。
- Friends Tycoon 地点详情在桌面端通过鼠标悬停或键盘聚焦展示，在手机端通过点击地点展示。
- 地点详情至少包含买地价格、升级费用、当前过路费，以及 1 到 4 级过路费表。

## 文案规范

- 语气像朋友提醒，不像后台系统。
- 少用技术词。
- 避免长段说明。
- 重要规则要明确，例如“提交后不能修改”。

示例：

- `慢慢答，不着急。`
- `已保存`
- `还差 3 题就可以提交`
- `提交后就不能改啦，确认提交吗?`

## 移动端要求

- 按钮高度适合手指点击。
- 文本框高度足够输入短段回答。
- 顶部进度固定清晰。
- 长答案自动换行。
- 页面不出现横向滚动。

# 设计规范

## 设计气质

`100 Q&As` 应该像一个轻松、亲密、适合朋友慢慢填写的小网页，而不是企业问卷或考试系统。

关键词：

- 温柔
- 清爽
- 私密
- 轻量
- 有陪伴感
- 手机端友好

## 页面布局

- 第一屏直接提供主要操作，不做营销式落地页。
- 手机端优先设计。
- 答题页每屏只承载少量信息，避免压迫感。
- 每页固定 5 题，题目和输入框之间要有足够呼吸感。
- 结果页以问题为核心，先看到题目，再看到朋友们的答案。

## 颜色与视觉

- 避免单一大面积紫色、深蓝、棕橙、米色主题。
- 推荐使用清爽浅底，搭配少量柔和强调色。
- 按钮状态要明确：可点击、不可点击、提交危险确认。
- 不使用复杂装饰，不做过度拟物。

## 交互规范

- 创建房间、复制链接、进入答题、提交答案都要有明确反馈。
- 创建房间页使用清晰的题库来源切换：默认题库 / 自定义题库。
- 自定义题库上传或粘贴后，要立即显示已识别题目数量。
- 题库未满足 100 题时，生成房间按钮仍可点击，并用提示说明当前识别题数和差几题。
- 草稿保存状态要轻提示，例如“已保存”。
- 提交前必须二次确认。
- 提交后所有输入框不可编辑。
- 未提交进入结果页时，要引导用户先完成答题。
- 本地原型可以展示房间进度和本地玩家切换入口，真实多人版本应收敛为参与者状态展示。

## 文案规范

- 语气像朋友提醒，不像后台系统。
- 少用技术词。
- 避免长段说明。
- 重要规则要明确，例如“提交后不能修改”。

示例：

- `慢慢答，不着急。`
- `已保存`
- `还差 3 题就可以提交`
- `提交后就不能改啦，确认提交吗?`

## 移动端要求

- 按钮高度适合手指点击。
- 文本框高度足够输入短段回答。
- 顶部进度固定清晰。
- 长答案自动换行。
- 页面不出现横向滚动。

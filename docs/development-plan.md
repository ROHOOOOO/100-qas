# 分步开发计划

## 当前推进原则

不要一口气做太多。每一阶段完成后都要能被用户打开、体验、验证。

## 阶段 0：需求与项目秩序

状态：已完成。

完成内容：

- 阅读用户提供的 `100 Q&As.docx`。
- 提取并确认 100 个问题。
- 确认第 23 题修正为“现在想吃什么?”。
- 确认 MVP 玩法。
- 创建 `docs/` 文档体系。
- 创建 `dev-days/` 每日开发记录体系。

## 阶段 1：本地可运行交互原型

状态：已完成。

目标：

- 创建无需安装依赖的网页原型。
- 用户可直接打开 `index.html` 体验。
- 跑通创建房间、输入昵称、分页答题、保存草稿、提交、查看结果的本地流程。

计划步骤：

1. 已完成：创建基础文件：`index.html`、`src/styles.css`、`src/app.js`、`src/questions.js`。
2. 已完成：写入 100 个问题。
3. 已完成：实现页面状态切换：首页、加入、答题页、结果页。
4. 已完成：实现每页 5 题。
5. 已完成：实现本地 `localStorage` 草稿保存。
6. 已完成并验证：提交后不可修改。
7. 已完成并验证：提交后按题目查看答案。
8. 已完成：提交确认使用页面内弹窗，而不是浏览器默认确认框。

验收：

- 不需要后端即可完整体验单设备流程。
- 当前已通过基础冒烟验证：创建房间、加入昵称、显示前 5 题、填写一题、翻到下一页。
- 当前已通过完整自动化验证：填满 100 题、取消一次提交确认、确认提交、检查锁定状态和结果页。

## 阶段 2：本地多人模拟

状态：已完成。

目标：

- 在同一浏览器中模拟多个玩家加入同一房间。
- 验证“未提交不能看答案，已提交才能看答案”的规则。

计划步骤：

1. 已完成：支持切换或新增本地玩家。
2. 已完成：展示房间参与者列表。
3. 已完成：展示已提交人数。
4. 已完成：验证结果页只显示已提交玩家答案。

验收：

- 可以用一个浏览器模拟 2 到 3 个朋友完成游戏。
- 当前已通过完整自动化验证：一个玩家提交、另一个玩家未提交；未提交玩家看不到结果，切回已提交玩家后结果页正常。

目标：

- 把本地数据操作抽象成数据访问层。
- 为接入数据库做准备。
- 保持当前静态网页可部署到 GitHub Pages。

计划步骤：

1. 已完成：增加 `src/config.js` 配置入口。
2. 已完成：默认保留本地模式。
3. 已完成：实现 Supabase RPC 读写适配。
4. 已完成：提供 Supabase 初始化 SQL：`supabase/schema.sql`。
5. 已完成：提供 GitHub Pages 与 Supabase 上线指南：`docs/deployment-guide.md`。
6. 已完成：填入真实 Supabase Project URL 和 publishable key。
7. 已完成：运行 `supabase/schema.sql` 后，验证在线多人流程。

验收：

- 替换存储实现时不需要大改 UI。
- 配置 Supabase 后，朋友可以打开同一网页直接加入房间、填写、提交、查看结果。

## 阶段 5：房间级自定义题库

状态：已完成。

目标：

- 不同房间可以绑定不同题量的题库；默认 100 题，自定义 1 到 100 题。
- 创建房间时支持默认题库和自定义题库。
- 朋友进入不同房间时，自动回答对应房间的问题。

计划步骤：

1. 已完成：前端创建房间页支持默认题库和自定义题库切换。
2. 已完成：支持上传 `.txt` / `.md` / `.csv` 纯文本题库文件。
3. 已完成：支持直接粘贴题目。
4. 已完成：答题页、结果页、进度和参与者状态读取房间题库。
5. 已完成：本地完整自动化验证上传自定义题库流程。
6. 已完成：在 Supabase SQL Editor 中运行最新版 `supabase/schema.sql`。
7. 已完成：运行线上自定义题库验收。

验收：

- 自定义题库识别出 1 到 100 题后即可创建房间。
- 房间创建后题库固定。
- 同一房间内玩家看到同一套题。
- 不同房间可以看到不同题库。

## 阶段 7：Friends Tycoon MVP

状态：未开始。

目标：

- 做出可供 2 到 6 位朋友在线同房间游玩的文字版大富翁。
- 支持房主开始、重开、解散房间。
- 支持 32 格地图、掷骰、移动、买地、付租、升级、破产和胜利结算。
- 支持聊天区与游戏记录分开。

建议小步顺序：

1. 设计 `Friends Tycoon` 数据模型和 Supabase SQL。
2. 做本地模式游戏房间原型，先跑通 2 人轮流掷骰。
3. 加入 32 格地图、玩家位置、现金和当前回合。
4. 加入买地、付租、升级到 4 级。
5. 加入破产出局和两种胜利条件。
6. 加入聊天区和游戏记录区。
7. 接入 Supabase RPC，做真实多人同步。
8. 做线上双玩家验收，再扩展到 6 人边界测试。

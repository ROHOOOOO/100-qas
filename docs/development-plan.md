# 分步开发计划

## 当前推进原则

不要一口气做太多。每一阶段完成后都要能被用户打开、体验、验证。

状态：已完成。

完成内容：

- 阅读用户提供的 `100 Q&As.docx`。
- 提取并确认 100 个问题。
- 确认第 23 题修正为“现在想吃什么?”。
- 确认 MVP 玩法。
- 创建 `docs/` 文档体系。
- 创建 `dev-days/` 每日开发记录体系。

## 阶段 1：本地可运行交互原型

状态：已完成。

目标：

- 创建无需安装依赖的网页原型。
- 用户可直接打开 `index.html` 体验。
- 跑通创建房间、输入昵称、分页答题、保存草稿、提交、查看结果的本地流程。

计划步骤：

1. 已完成：创建基础文件：`index.html`、`src/styles.css`、`src/app.js`、`src/questions.js`。
2. 已完成：写入 100 个问题。
3. 已完成：实现页面状态切换：首页、加入、答题页、结果页。
4. 已完成：实现每页 5 题。
5. 已完成：实现本地 `localStorage` 草稿保存。
6. 已完成并验证：提交后不可修改。
7. 已完成并验证：提交后按题目查看答案。
8. 已完成：提交确认使用页面内弹窗，而不是浏览器默认确认框。

验收：

- 不需要后端即可完整体验单设备流程。
- 当前已通过基础冒烟验证：创建房间、加入昵称、显示前 5 题、填写一题、翻到下一页。
- 当前已通过完整自动化验证：填满 100 题、取消一次提交确认、确认提交、检查锁定状态和结果页。

## 阶段 2：本地多人模拟

状态：已完成。

目标：

- 在同一浏览器中模拟多个玩家加入同一房间。
- 验证“未提交不能看答案，已提交才能看答案”的规则。

计划步骤：

1. 已完成：支持切换或新增本地玩家。
2. 已完成：展示房间参与者列表。
3. 已完成：展示已提交人数。
4. 已完成：验证结果页只显示已提交玩家答案。

验收：

- 可以用一个浏览器模拟 2 到 3 个朋友完成游戏。
- 当前已通过完整自动化验证：一个玩家提交、另一个玩家未提交；未提交玩家看不到结果，切回已提交玩家后结果页正常。

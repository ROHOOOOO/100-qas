# 同词相遇

2026-11-02 首版实现；2026-11-05 扩展为 2–6 人，用户确认全员同词才成功。此模块使用现有 Friends Games 账号，不设电脑、房间聊天、胜负或排行榜。

## 房间与流程

1. 登录后创建房间，输入 1–60 字名称。通过邀请链接或六位房间码加入，支持 2–6 个不同账号。
2. 开局前可以继续邀请，所有成员准备后由房主点击“开始联想”；至少两人。开局后固定成员，不允许新成员中途加入；原成员可随时回来继续。第一轮自由输入，每人一个词。
3. 提交后锁定，只有本人能看到自己的词。服务端不会向其他成员发送未揭晓的词；只显示“已提交”。
4. 全员提交后，一次性揭晓所有词。所有人的词归一化后相同才成功；只有两人或多数人同词时继续游戏。否则等待全员准备后，自动开始下一轮。
5. 下一轮应选择与上一轮所有词都有关的新词。关联由玩家判断，不调用语义判定或词典服务。
6. 结束后可返回创建新房间再次挑战。

## 输入与匹配

- 中文为 2–6 个汉字，英文为 2–15 个 ASCII 字母。禁止数字、标点、表情、中英混写及词内空格；忽略首尾空白。
- 英文忽略大小写，中文采用固定繁体转简体字形映射；比较结果一致，展示保留提交原文。
- 字形映射来自 OpenCC 字表，保留授权声明，不作词义或同义词匹配。
- 新词不得与紧邻上一轮的任意一个词相同，按上述归一化规则比较。更早轮次的词允许复用。
- 提交前做前端提示，服务端独立验证；非法提交不占用本轮提交机会。

## 计时、恢复与结束

- 每轮使用服务端开始时间共享 60 秒倒计时，时间到仅提醒，仍可提交；不自动提交、公开或判负。
- 等待成员准备期间不倒计时。本局耗时从第一轮开始到成功或中断，包含两轮之间的准备时间。
- 未提交草稿按账号、房间及轮次保存在本浏览器。换语言、正常同步、刷新不清除输入；换设备不迁移未提交草稿。
- 提交结果不确定时保留操作凭证，刷新后仍可重试；相同凭证只执行一次。
- 刷新、离开、断线不结束房间，可从账号记录回到原房间。
- 任意成员可经确认结束本局，标记“已中断 · 未相遇”，保留已揭晓历史；未揭晓的提交从游戏数据中清除。

## 记录与权限

所有成员的账号均记录房间、参与人、已揭晓轮数、创建/开始/结束时间和结果。每轮保存原词、当时用户名、开始和揭晓时间。用户名变化不改写已揭晓历史。

账号及游戏入口显示最近 100 个房间；房间中全部已揭晓轮次可按每页 25 条向前加载，记录不会因分页被删除。结束后成员仍可查看自己的房间历史。非成员仅能看到邀请页面的房间名及是否可加入，不能读取成员、词语或历史。

## 界面与发布

- 首页与导航新增入口，名称在三种语言中统一保持“同词相遇”。系统文案支持简体、繁体和英文，用户词语和房间名不翻译。
- 房间显示人数、房主、每人准备/提交状态和总进度。六人词卡完整展示；桌面左右展示当前轮与历史，手机上下排列。开始、揭晓、等待、成功与中断均有明确状态。
- 本地模式保存在当前浏览器，供演示和回归；跨设备房间依靠 Supabase。
- 已有线上双人版先执行 `supabase/words-multiplayer.sql`，再发布前端；全新安装使用 `supabase/words.sql` 或完整 `supabase/schema.sql`，都包含相同升级。
- 升级保留双人房间、历史姓名与原词、未结束房间的进度及私密提交。升级脚本可重复运行；新表禁止客户端直接读写。
